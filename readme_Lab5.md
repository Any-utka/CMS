## Цель работы

Закрепить ключевые практики безопасности WordPress: управление ролями и паролями, обновления, базовое hardening (wp-config.php, права, отключение редактора), резервное копирование, мониторинг активности и поэтапная настройка All In One WP Security & Firewall (AIOS) для защиты от брутфорса, базового WAF и контроля прав.

### Ход выполнения

#### Шаг 1. Подготовка среды

1. В локальной установке WordPress переходим в админ-панель

2. Убеждаемся, что используем учетную запись с правами Administrator

3. Далее открываем файл wp-config.php и включаем режим отладки, установив: ```define('WP_DEBUG', true);```

#### Шаг 2. Управление ролями и паролями

1. Переходим в раздел: ```Users → Add New```

2. Создаем тестового пользователя

   ![Img-1](https://imgur.com/fsl05YY.png)

3. После этого открываем раздел: ```Users → All Users```

4. Проверяем, что пользователь создан и убеждаемся, что все администраторы используют сложные пароли

![Img-2](https://imgur.com/x5yfPh0.png)

#### Шаг 3. Обновление ядра, тем и плагинов

1. Переходим в раздел: ```Dashboard → Updates```

2. Проверяем наличие обновлений для:

   - ядра WordPress

   - установленных тем

   - установленных плагинов

    ![Img-3](https://imgur.com/AQck7pc.png)

    При наличии обновлений выполняем обновление до последних версий

    ![Img-4](https://imgur.com/rMSFdxc.png)

3. Далее включаем автоматические обновления плагинов в разделе: ```Plugins → Installed Plugins → Enable auto-updates```

    ![Img-5](https://imgur.com/hAeQtnE.png)
    ![Img-6](https://imgur.com/qBGmoj6.png)

4. После обновления проверяем корректность работы сайта:

   - открывается главная страница

   - нет ошибок

   - админ-панель работает корректно

#### Шаг 4. Базовое Hardening

Для повышения безопасности сайта выполняем несколько базовых настроек

1. Сначала запрещаем редактирование файлов через админ-панель. Для этого в файл ```wp-config.php``` добавляем строку: ```define('DISALLOW_FILE_EDIT', true);```

    Это предотвращает изменение файлов темы или плагинов через админку в случае взлома аккаунта администратора

    ![Img-7](https://imgur.com/eUEWr0C.png)

2. Далее защищаем файл конфигурации WordPress. В файл ```.htaccess``` добавляем правило:

    ```htaccess
        <files wp-config.php> 
        order allow,deny 
        deny from all 
        </files>
    ```

    ![Img-8](https://imgur.com/x25Ckz2.png)

    Это запрещает доступ к файлу wp-config.php через браузер

#### Шаг 5. Установка и настройка плагина безопасности

1. Для дополнительной защиты устанавливаем плагин ```All In One WP Security & Firewall```

   ![Img-9](https://imgur.com/W2LuKa8.png)

2. Переходим в раздел: ```Plugins → Add New```

    - Находим плагин All In One WP Security & Firewall, устанавливаем и активируем его

    - После активации в админ-панели появляется раздел WP Security

#### Шаг 6. Проверка защиты от Brute Force

### Контрольные вопросы

1. Почему ```DISALLOW_FILE_EDIT``` и правильные права на ```wp-config.php``` существенно уменьшают риск пост-эксплойта?

    В WordPress параметр ```DISALLOW_FILE_EDIT``` отключает редактор файлов в админ-панели. Если злоумышленник получит доступ к аккаунту администратора, он не сможет изменить файлы темы или плагинов через интерфейс WordPress и внедрить вредоносный код

    Файл ```wp-config.php``` содержит данные подключения к базе данных и ключи безопасности. Ограничение доступа к этому файлу и правильные права доступа предотвращают его чтение через веб-сервер и уменьшают риск компрометации сайта

2. Какие параметры Login Lockdown/Firewall вы выбрали и почему именно такие (обоснуйте баланс безопасности и UX)?
    В плагине All In One WP Security & Firewall были выбраны параметры:

    - Max Login Attempts — 5

    - Login Retry Time Period — 15 минут

    - Lockout Time — 30 минут

    Такие значения позволяют защититься от brute force атак, но при этом обычные пользователи могут несколько раз ошибиться при вводе пароля. Также был включён Basic Firewall и защита от Bad Query Strings и XSS для блокировки распространённых атак

3. Чем отличаются меры защиты на уровне WordPress (плагин/WAF) от мер на уровне веб-сервера и ОС?

    Защита на уровне ```WordPress``` реализуется через плагины и настройки системы. Она контролирует вход пользователей, регистрацию, запросы и действия внутри сайта

    Защита на уровне веб-сервера управляет доступом к файлам, правилами ```.htaccess```, блокировкой IP и обработкой HTTP-запросов

    Защита на уровне операционной системы включает управление пользователями сервера, правами доступа и настройку сетевого ```firewall```. Эти меры защищают весь сервер, а не только ```WordPress```

4. Что обязательно включать в "полный" бэкап WP и как вы проверяете, что восстановление действительно работает?

    Полный бэкап должен включать:

    - базу данных сайта

    - папку ```wp-content``` (темы, плагины, uploads)

    - файл ```wp-config.php```

    Проверка восстановления выполняется так: создаётся резервная копия, затем удаляются тестовые данные (например пользователь или изображение), после чего база данных восстанавливается из бэкапа и проверяется, вернулись ли удалённые данные
